
# لوحة الإدارة (Admin Dashboard) — نسخة معتمدة

تمت الإجابة على الأسئلة. الإعدادات المعتمدة:
- **أول أدمن**: الجوال `00967782566694` (سيُربط تلقائياً عند تسجيل الدخول بهذا الرقم).
- **اعتماد المتاجر**: يدوي — أي متجر جديد يُنشأ بحالة `pending` ولا يظهر للعملاء حتى يوافق الأدمن.
- **نسبة العمولة**: مُتغيّر داخل اللوحة (`/admin/settings`) يستطيع الأدمن تغييره وقت ما يشاء، القيمة الابتدائية `0%`.

---

## 1) البنية الأمنية

- توسيع `app_role` بقيمة `admin`.
- دالة `is_admin()` (SECURITY DEFINER) + سياسات RLS إدارية على كل الجداول الحساسة دون كسر سياسات العميل/التاجر.
- Trigger على `profiles`: إذا كان `phone = '00967782566694'` يُمنح دور `admin` تلقائياً (يعمل أيضاً عند تسجيل الدخول لأول مرة).
- صفحات `/admin/*` محمية في الواجهة + RLS يمنع أي طلب مباشر من غير الأدمن.

## 2) شاشات اللوحة

```text
/admin
 ├── /overview        مؤشرات + رسوم بيانية
 ├── /users           بحث، حظر/تفعيل، ترقية لأدمن، إعادة ضبط PIN
 ├── /merchants       طلبات افتتاح متاجر (موافقة/رفض)
 ├── /stores          كل المتاجر، تعليق/تفعيل، تعديل موقع/عمولة خاصة
 ├── /products        فهرس عام + إدارة الكتالوج المشترك
 ├── /orders          كل الطلبات (أونلاين + داخل المحل) مع فلاتر
 ├── /credit          الذمم بين العملاء والتجار + كشوف
 ├── /wallets         الموافقة على شحن المحافظ + سجل العمليات
 ├── /returns         فضّ النزاعات بين العميل والتاجر
 ├── /banners         إنشاء/جدولة بانرات (عام أو متجر)
 ├── /notifications   إرسال إشعار جماعي (الكل/عملاء/تجار/مدينة)
 ├── /reports         تقارير المبيعات والعمولات + تصدير CSV
 └── /settings        نسبة العمولة، رسوم التوصيل، تفعيل طرق الدفع، رقم دعم...
```

## 3) اعتماد المتاجر يدوياً

- إضافة عمود `status` على `stores` بقيم: `pending | active | suspended | rejected`.
- المتاجر الحالية تتحوّل إلى `active` (لمنع كسر التطبيق).
- استعلامات العميل (الرئيسية + صفحة متجر) تُفلتر `status = 'active'` فقط.
- التاجر يرى متجره ولوحته حتى لو كان `pending`، مع شارة "بانتظار الموافقة".
- في `/admin/merchants` زر **موافقة / رفض / تعليق**.

## 4) نظام العمولة

- جدول `app_settings(key text pk, value jsonb)` يخزّن `default_commission_pct`, `delivery_fee`, إلخ.
- عمود اختياري `commission_pct` على `stores` (يطغى على القيمة الافتراضية).
- عند إنشاء أي طلب: trigger يحسب `commission_amount = total * pct` ويخزّنه على `orders` للتقارير.
- صفحة `/admin/settings` تعرض النسبة الحالية وتسمح بتعديلها لحظياً.
- صفحة `/admin/stores` تسمح بتعديل عمولة متجر بعينه.

## 5) مؤشرات `/admin/overview`

- إجمالي المستخدمين / التجار النشطين / الطلبات اليوم.
- إجمالي المبيعات (أونلاين + داخل المحل) — يوم/أسبوع/شهر.
- العمولات المستحقة، رصيد المحافظ المعلّق، الذمم المفتوحة، إرجاعات قيد المراجعة.
- رسم بياني لأفضل 5 متاجر و5 منتجات.

## 6) صلاحيات تنفيذية مباشرة من اللوحة

- **مستخدمين**: حظر/تفعيل، إعادة ضبط PIN، ترقية لأدمن، عرض كل طلبات وذمم العميل.
- **محافظ**: عمليات `pending` → موافقة/رفض → الرصيد يتحدّث تلقائياً (الـ trigger موجود).
- **إشعارات جماعية**: اختر شريحة (الكل/العملاء/التجار/مدينة) واكتب نصاً.
- **بانرات**: نشر/إخفاء/جدولة.

## 7) تفاصيل تقنية

- ملفات جديدة:
  - `src/routes/admin.tsx` (Shell + حماية الدور)
  - `src/components/AdminShell.tsx` (تنقّل جانبي)
  - `src/routes/admin.{overview,users,merchants,stores,products,orders,credit,wallets,returns,banners,notifications,reports,settings}.tsx`
- migration واحد يتضمّن:
  1. توسيع `app_role` بقيمة `admin`.
  2. `is_admin()` + سياسات RLS إدارية.
  3. `stores.status` + ترقية الموجود إلى `active`.
  4. `app_settings` + قيم افتراضية (`default_commission_pct = 0`).
  5. `orders.commission_pct`, `orders.commission_amount` + trigger للحساب.
  6. Trigger تلقائي يمنح `admin` لأي ملف عمود `phone='00967782566694'`.
  7. RPCs آمنة: `admin_approve_wallet_tx`, `admin_set_user_role`, `admin_set_store_status`, `admin_broadcast_notification`, `admin_update_setting`.

## 8) خطة التنفيذ بالترتيب

1. Migration (الخطوة الأهم — تحتاج موافقتك).
2. AdminShell + حماية الدور + `/admin/overview`.
3. شاشات: users / merchants / stores / orders.
4. شاشات: wallets / returns / credit.
5. شاشات: banners / notifications / reports / settings.
6. تعديل صفحة الرئيسية وصفحة المتجر لتفلتر `status='active'` فقط.
7. اختبار شامل (تسجيل دخولك بالرقم → ظهور اللوحة → الموافقة على متجر تجريبي → تأكد ظهوره للعملاء).

موافقتك تعني البدء فوراً بالـ migration ثم تنفيذ بقية الخطوات بالتسلسل.
