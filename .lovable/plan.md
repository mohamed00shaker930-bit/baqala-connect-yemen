# تنفيذ الملاحظات الكاملة على 3 مراحل

سأنفّذ المراحل الثلاث بالتسلسل. القرارات الافتراضية للأسئلة المفتوحة (يمكن تعديلها):

- **الخرائط**: استخدام موصّل Google Maps المتوفّر في Lovable (لا يحتاج مفتاحاً منك).
- **المحفظة**: شحن يدوي عبر تحويل بنكي/محفظة إلكترونية يوافق عليه التاجر/الأدمن (بدون بوابة دفع الآن — يمكن إضافة Stripe لاحقاً).
- **اللغات**: عربي افتراضي + إنجليزي عبر `i18next` و `react-i18next`.

سأنفّذ كل مرحلة على دفعات صغيرة وأتحقّق بعد كل دفعة قبل الانتقال للتالية.

---

## المرحلة 1 — إصلاحات سريعة (دفعة واحدة)

1. **PIN يصبح 4 خانات**: تعديل `PIN_LENGTH = 4` في `src/lib/app-lock.ts` وحقول `LockScreen` و`SetPinDialog`.
2. **مدة القفل قابلة للاختيار**: قائمة منسدلة في الإعدادات (كل دخول / 10د / 30د / 1س / 3س / 8س) تُحفظ في `localStorage` وتُستخدم في منطق idle-timeout.
3. **القفل عند الخمول والقفل عند الإخفاء اختياريّان**: مفتاحَا Switch منفصلَان في إعدادات الأمان.
4. **القفل يعمل للتاجر أيضاً**: نقل `<LockScreen />` من نطاق العميل إلى `src/routes/__root.tsx` بعد جلسة auth.
5. **OTP/تسجيل دخول auto-dismiss**: تقليل `duration` للـ toast الناجح + استدعاء `toast.dismiss()` عند الانتقال.
6. **مشاركة المنتج اليدوي مع المكتبة**: التحقّق من التريغر `sync_product_to_catalog` (موجود) + إضافة فحص بصري في `CatalogPicker` يؤكد ظهور المنتج الجديد للتجار الآخرين.

## المرحلة 2 — ميزات متوسطة

### 2.1 الموقع و"المتاجر الأقرب"
- توسيع جدول `locations` ليشمل: `lat`, `lng`, `label` (منزل/عمل/مخصص), `landmark` (نص وصف معلم).
- إضافة `lat/lng/address` للجدول `stores`.
- شاشة "اختر موقعي" تستخدم Google Maps JS API (متاح عبر موصّل Lovable):
  - تحديد تلقائي عبر `navigator.geolocation` + خيار سحب الدبّوس يدوياً.
  - حقل وصف معلم.
- العميل يحفظ عدّة مواقع ويختار النشط.
- التاجر يضبط موقع متجره عند التسجيل + من إعدادات المتجر.
- `home.tsx` يحسب المسافة (Haversine في SQL view) ويرتّب المتاجر بالأقرب أولاً مع عرض المسافة بالكيلومتر.

### 2.2 المفضلة
- جدول `favorites(user_id, target_type[store|product], target_id)` + RLS + GRANTs.
- زر قلب على بطاقة المتجر وبطاقة المنتج.
- قسم "المفضلة" في `/profile` بتبويبَين (متاجر / منتجات).

### 2.3 اطلب مرة أخرى
- استعلام آخر 5 طلبات للعميل.
- بطاقة أفقية في رأس `/home` + قسم في `/profile`.
- زر "اطلب مرة أخرى" يعبّئ سلة قابلة للتعديل ثم ينتقل لـ `/cart`.

### 2.4 المرتجعات
- إضافة حالة `returned` لـ `order_status` + حقل `return_reason`.
- زر "طلب إرجاع" في تفاصيل الطلب المُسلَّم.
- شاشة "المرتجعات" في `/profile` تعرض حالة كل طلب إرجاع.
- شاشة التاجر تعرض طلبات الإرجاع المعلّقة مع موافقة/رفض.

## المرحلة 3 — ميزات كبيرة

### 3.1 الإشعارات
- جدول `notifications(user_id, title, body, type, read_at, link)` + RLS.
- جدول `notification_broadcasts` للأدمن (broadcasts تتحوّل لإشعارات فردية عبر دالة).
- مكوّن أيقونة الجرس مع badge للعدّاد غير المقروء في `CustomerShell` و`MerchantShell`.
- شاشة `/notifications` تعرض القائمة وتعلّمها مقروءة عند الفتح.
- شاشة `/profile/notification-preferences` لتمكين/إيقاف الأنواع.
- شاشة لوحة الأدمن `/admin/broadcasts` (محمية بدور `admin`) لإرسال إشعار لشريحة.
- Realtime subscription للتحديث الفوري.

### 3.2 محفظة العميل
- جدولا `wallet_accounts(user_id, balance)` + `wallet_transactions(account_id, type[topup|spend|refund], amount, status, ref, approved_by)`.
- RPC `wallet_request_topup` لإنشاء طلب شحن (مع رقم مرجعي + صورة إيصال اختيارية).
- شاشة الأدمن/التاجر تعتمد الشحن → التريغر يحدّث الرصيد.
- استخدام الرصيد كوسيلة دفع في `/cart` (يتحقّق من كفاية الرصيد، يخصم عند تأكيد الطلب).
- اختصار "رصيدي" في الشريط العلوي لـ `/home` + بطاقة في `/profile` مع سجل الحركات.

### 3.3 الإعلانات المتحركة
- جدول `ads(image_url, link_url, title, active, starts_at, ends_at, sort_order)`.
- شاشة أدمن بسيطة لإدارتها.
- Carousel (Embla autoplay) فوق قائمة المتاجر في `/home`.

### 3.4 تعدد اللغات (ar/en)
- تثبيت `i18next`, `react-i18next`, `i18next-browser-languagedetector`.
- ملفّان `src/i18n/ar.json` و `src/i18n/en.json` يغطّيان كل النصوص الموجودة.
- استبدال النصوص العربية الحرفية في الكود بـ `t('key')`.
- مفتاح تبديل في `/profile/settings` + تحديث `document.dir` و `lang` ديناميكياً.
- اختيار افتراضي: لغة المتصفّح وإلا عربي.

## ملاحظات تنفيذ تقنية

- **الترتيب داخل كل مرحلة**: تعديلات الكود أولاً ثم migrations الجداول الجديدة في batch واحد لكل قسم لتجنّب reset لـ types.
- **الأمان**: كل جدول جديد يأخذ RLS + GRANTs + سياسات `auth.uid()` فقط (لا anon).
- **Google Maps**: استخدام browser key من الموصّل `VITE_LOVABLE_CONNECTOR_GOOGLE_MAPS_BROWSER_KEY` وتحميل JS API بـ `loading=async`.
- **التحقّق**: بعد كل مرحلة، أفتح المعاينة وأختبر السيناريوهات الرئيسية وأبلغك بالنتيجة قبل المتابعة.
- **ملف الاختبار**: سأحدّث `/mnt/documents/test-checklist.md` في نهاية كل مرحلة بحالة "تم" مقابل البنود المنفّذة.
