# تحويل التطبيق إلى مرجع أساسي للبقالة (أونلاين + داخل المحل)

الهدف: يستخدم التاجر التطبيق لكل مبيعاته — سواء من العملاء عبر الإنترنت أو من الذين يحضرون إلى المحل — مع تقرير موحّد آخر اليوم.

## 1. نقطة بيع سريعة داخل المحل (POS)

شاشة جديدة `/merchant/pos` مخصّصة لخدمة العميل الحاضر بأقل وقت ممكن:

- زر كبير "مسح باركود" يفتح كاميرا الجوال ويقرأ الباركود مباشرة (مكتبة `@zxing/browser`).
- بمجرد قراءة الباركود → يُضاف المنتج تلقائياً إلى الفاتورة الحالية بكمية 1، ويصدر صوت تأكيد قصير.
- لو الباركود غير معروف → نافذة سريعة "منتج جديد" (اسم + سعر) تحفظه وتربطه بالباركود فوراً.
- بحث يدوي بالاسم كبديل عند تعطل الكاميرا.
- قائمة الأصناف الحالية بجانب الشاشة مع: كمية (+/−)، حذف، الإجمالي يتحدث لحظياً.
- طريقة الدفع: نقداً / محفظة (جيب، جوالي، حاسب، ون كاش) / آجل.
- زر "إتمام البيع" → يحفظ الفاتورة فوراً ويطبع/يعرض إيصالاً قابلاً للمشاركة (PDF بسيط أو شاشة إيصال).

ملاحظات تصميم:
- أزرار كبيرة، خط واضح، الشاشة تعمل بيد واحدة.
- لا حقول إجبارية للعميل (الاسم/الرقم اختياري فقط للآجل).
- يعمل بدون إنترنت لفترة قصيرة (queue محلي يُرفع عند عودة الاتصال — مرحلة لاحقة).

## 2. ربط الباركود بالمنتجات

في شاشة "منتج جديد/تعديل" يُضاف:
- حقل `barcode` (نصي، فريد داخل المتجر).
- زر "مسح" يفتح الكاميرا ويملأ الحقل تلقائياً.

## 3. تمييز مصدر الطلب

كل فاتورة تُسجَّل في جدول `orders` الحالي مع حقل جديد `channel`:
- `online` = من تطبيق العميل (الوضع الحالي).
- `in_store` = من شاشة POS داخل المحل.

طلبات `in_store` تتجاوز مراحل (sent → accepted → preparing …) وتُسجَّل مباشرة بحالة `delivered`، لأن العميل أخذ المنتج فعلياً.

## 4. تقرير آخر اليوم `/merchant/reports`

صفحة جديدة تعرض:
- ملخّص اليوم: إجمالي المبيعات، عدد الفواتير، متوسط الفاتورة.
- تقسيم حسب المصدر: أونلاين مقابل داخل المحل (أرقام + شريط بسيط).
- تقسيم حسب طريقة الدفع (نقدي، كل محفظة، آجل).
- أعلى 5 منتجات مبيعاً اليوم.
- محدّد فترة: اليوم / أمس / آخر 7 أيام / الشهر / نطاق مخصص.
- زر تصدير CSV للفواتير.

## 5. تحديثات قاعدة البيانات

ترحيل واحد:
- `products.barcode TEXT` + فهرس فريد `(store_id, barcode)`.
- `orders.channel` enum `online | in_store` بقيمة افتراضية `online`.
- (اختياري) `orders.cashier_id` للإشارة إلى مَن أنشأ فاتورة المحل.

## 6. التنقّل

شريط التاجر السفلي يُضاف إليه:
- "نقطة البيع" (أيقونة باركود) — وصول بنقرة واحدة.
- "التقارير" (أيقونة رسم بياني).

---

### تفاصيل تقنية مختصرة

- مكتبة مسح الباركود: `@zxing/browser` (تعمل في المتصفح عبر `getUserMedia`، بدون تطبيق أصلي).
- شاشة POS: ملف `src/routes/merchant.pos.tsx`، state داخلي للفاتورة الحالية، حفظ نهائي عبر `supabase.from("orders").insert(...)` + `order_items`.
- التقارير: ملف `src/routes/merchant.reports.tsx`، استعلامات `select` مُجمَّعة على `orders` المفلترة بـ `store_id` و`created_at`.
- جميع التغييرات على واجهة التاجر — لا تأثير على تدفق العميل الحالي.
