# خطة بناء تطبيق بقالتي (Baqalati)

تطبيق ويب PWA عربي RTL يخدم **طرفين**: العميل والتاجر صاحب البقالة، مع قاعدة بيانات مشتركة.

## نظرة عامة

- **التقنية**: TanStack Start + React + Tailwind + Lovable Cloud (قاعدة بيانات + مصادقة)
- **اللغة**: عربية افتراضياً، RTL كامل
- **الألوان**: تركواز هادئ #0E7C86 كلون أساسي، نص داكن #1A1A1A، خلفيات فاتحة
- **التصميم**: أزرار كبيرة، أيقونات واضحة، نص قليل، يعمل على هواتف ضعيفة

## المصادقة والأدوار

- تسجيل بالجوال + OTP **وهمي** (الكود يظهر على الشاشة مباشرة - مثل `123456` أو يُولّد عشوائياً ويُعرض في رسالة Toast)
- عند أول تسجيل: شاشة اختيار الدور → **عميل** أو **تاجر**
- التاجر بعد اختيار الدور يكمل بيانات متجره (اسم، موقع على الخريطة، فئة النشاط، ساعات العمل)
- الدور محفوظ في جدول `user_roles` منفصل (لمنع تصعيد الصلاحيات)

## واجهة العميل (`/`)

1. **الصفحة الرئيسية**: قائمة البقالات القريبة (مرتبة بالمسافة، مفتوحة/مغلقة، التقييم)
2. **تحديد الموقع**: خريطة + وصف معلم + رقم جوال، حفظ مواقع متعددة (بيت/عمل/أخرى)
3. **صفحة المتجر**: منتجات حسب الفئات + بحث داخلي
4. **السلة والدفع**: مراجعة، اختيار موقع، اختيار طريقة الدفع (نقداً عند الاستلام / آجل)
5. **تتبع الطلب**: شريط حالة (مُرسل ← مقبول ← قيد التحضير ← خرج للتوصيل ← تم التوصيل)
6. **دفتر الأجل**: عرض الرصيد لكل متجر + كشف الحركات (للقراءة فقط) + مشاركة كصورة/PDF
7. **سجل الطلبات + إعادة الطلب**
8. **التقييمات** بعد التوصيل
9. **الإعدادات والملف الشخصي**

## واجهة التاجر (`/merchant`)

1. **لوحة التحكم**: ملخص الطلبات اليوم، الجديد، الإيرادات، الديون المستحقة
2. **الطلبات الواردة**: قائمة الطلبات الجديدة مع زر قبول/رفض، تحديث الحالة خطوة بخطوة
3. **إدارة المنتجات**: إضافة/تعديل/حذف منتجات، رفع صور، أسعار، توفر/نفاد، فئات
4. **إدارة الفئات**: إنشاء وترتيب فئات المنتجات
5. **دفتر الأجل**:
   - قائمة العملاء الذين عليهم رصيد
   - لكل عميل: سجل المديونيات والدفعات + الرصيد الحالي
   - تسجيل دفعة جديدة (دفع جزء أو كل الرصيد)
   - الموافقة/الرفض على طلبات البيع بالأجل الجديدة
6. **إعدادات المتجر**: الاسم، الموقع، الساعات، رسوم التوصيل، حالة الفتح/الإغلاق
7. **التقييمات**: عرض تقييمات العملاء (للقراءة)

## التنفيذ على مراحل

### المرحلة 1 — البنية الأساسية + MVP العميل
- تفعيل Lovable Cloud
- إنشاء جداول قاعدة البيانات + RLS + الصلاحيات
- نظام التسجيل (جوال + OTP وهمي) + اختيار الدور
- توجيه تلقائي: العميل → `/`، التاجر → `/merchant`
- واجهة العميل: تحديد الموقع → عرض المتاجر → تصفح المنتجات → سلة → طلب نقدي → تتبع الحالة → سجل

### المرحلة 2 — لوحة التاجر الأساسية
- لوحة تحكم بسيطة + استقبال الطلبات + تحديث الحالات
- إدارة المنتجات والفئات والمخزون
- إعدادات المتجر

### المرحلة 3 — البيع بالأجل (الطرفين)
- طلب البيع بالأجل من العميل
- الموافقة/الرفض من التاجر
- دفتر الأجل: تسجيل المديونيات والدفعات
- عرض الكشف للعميل + المشاركة/التصدير
- إشعارات بكل قيد جديد

### المرحلة 4 — التقييمات والتحسينات
- تقييم المتجر بعد التوصيل
- إشعارات حالة الطلب
- صقل بصري + حالات الفراغ + التحميل

## التفاصيل التقنية

### جداول قاعدة البيانات
- `profiles` (id, phone, name, created_at)
- `user_roles` (id, user_id, role: 'customer'|'merchant') — منفصل لأمان الصلاحيات
- `locations` (id, user_id, label, lat, lng, landmark_text, phone)
- `stores` (id, owner_id, name, area, lat, lng, is_open, rating, delivery_info)
- `categories` (id, store_id, name, sort_order)
- `products` (id, store_id, category_id, name, image_url, price, in_stock)
- `orders` (id, customer_id, store_id, total, payment_method, status, note, location_id, created_at)
- `order_items` (id, order_id, product_id, name, price, qty, note)
- `credit_accounts` (id, customer_id, store_id, balance, status)
- `credit_transactions` (id, account_id, type: 'charge'|'payment', amount, date, order_id)
- `ratings` (id, customer_id, store_id, stars, comment, date)

### سياسات RLS الرئيسية
- العميل يرى/يعدل بياناته فقط
- التاجر يرى/يعدل بيانات متجره وطلباته وعملاء الأجل عنده فقط
- المنتجات والمتاجر قراءة عامة (anon) للتصفح
- دفتر الأجل خاص بين العميل والمتجر المعني فقط

### الخريطة
- استخدام Google Maps Platform connector (سيُطلب من المستخدم تفعيله عند الحاجة لتحديد الموقع)
- بديل: حقل إحداثيات يدوي + وصف نصي إذا لم يُفعّل

### قاعدة لا ربا
- لا فوائد، لا غرامات تأخير، لا أي زيادة على الرصيد مهما طال الزمن

## ملاحظات

- **OTP وهمي**: الكود يظهر للمستخدم في رسالة على الشاشة (toast/dialog) للتجربة. لاحقاً نربط Twilio.
- **لا يوجد توصيل من المنصة**: التاجر يحدث الحالة فقط، لا نظام سائقين.
- **خفيف وسريع**: skeleton loaders، صور مضغوطة، تخزين مؤقت للقوائم.
- المرحلة 1 و 2 سأبنيهما في هذه الجلسة. المراحل 3 و 4 نكملها بعد ما تجرب الأساس وتعطيني ملاحظات.
